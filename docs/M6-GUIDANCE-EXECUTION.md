# Single registered guidance comparison execution

The final source clearance reviews all 190 enumerated in-window SEC filing primaries for the 107 source-eligible events, with earlier original filings used to reconcile publication chronology. It adds a soft appointment caveat to ADSK's May 2025 event and hard unresolved-provenance/scope dispositions to CRWD's June 2025 event and ZS's November 2025 and February 2026 events. These additive decisions apply the existing taxonomy before closing outcomes and preserve every earlier frozen mask. [Final review](../reports/m6-guidance-final-source-review-2026-11-23.json)

The clean source pool is now 43 training events and 51 held events, each spanning 19 issuers. The all-defined sensitivity retains 51 training and 53 held events across 20 issuers. Three earlier hard-held exclusions remain in metadata solely to fix each full held block's first feature cutoff. No outcome determines a source mask. Dated older civil-court proceedings are treated as public before the window absent evidence of sealing; this source-availability inference and other coverage limitations are explicit in the review.

The registered models, three chronological folds, feature transform, ridge penalty, bootstrap seeds/replicates and all thresholds remain unchanged. Each fold needs at least 20 common fit rows and 10 issuers, with mature labels and a usable guidance column. The clean held pool must satisfy the registered row, issuer, session, gap-sign, revision-sign and fold support floors. Passing additionally requires at least 5% relative MSE reduction, a strictly positive lower endpoint of the outer 99% issuer/session bootstrap envelope, and nonnegative sensitivity improvement. A development pass qualifies only fresh-study scoping. [Protocol](../config/m6-guidance-protocol-v2.json) · [Scorer](../nre/m6_guidance_compare.py)

Execution first acquires labels privately and publishes only commitments, request/response digests, maturity times and quality dispositions. Existing training-opening and prior-anchor commitments must replay. Event-level prices, returns, targets and forecasts never enter GitHub. The acquisition manifest must be committed before fitting. The scoring workflow exclusively creates `reports/m6-guidance-attempt-v2-001.json` through GitHub before fitting. Creation deliberately omits an existing-file SHA and requires HTTP 201, so any existing claim, including a job rerun, prevents a second attempt. The claim binds the protocol, acquisition manifest, execution configuration, commit and workflow run. A partial failure consumes the logged attempt; the attempt file is never overwritten. [Workflow](../.github/workflows/m6-guidance-test.yml)

The scoring process reacquires private records and requires identical label commitments, source quality, maturity and request hashes. Changes only to provider response-byte digests are recorded separately; they cannot change labels, membership or settings. Synthetic tests cover chronological leakage, common rows, constant guidance, gate boundaries, request bounds, replay mismatches and disclosure controls. This is retrospective development using a selected historical roster and reconstructed clocks; it establishes no independent validation or trading profitability. The single comparison's result is the agreed decision point.
